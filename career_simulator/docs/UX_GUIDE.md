# UX-гайд Карьериста

## Цель

Интерфейс должен ощущаться как аккуратное мобильное приложение внутри Telegram: минимум лишнего текста, понятная иерархия, предсказуемые кнопки и одинаковое оформление от экрана к экрану.

## Структура экрана

Каждый основной экран строится одинаково:

1. заголовок `Карьерист · Раздел`;
2. информация, необходимая для решения именно здесь;
3. короткое объяснение механики только там, где оно действительно нужно;
4. кнопки действий;
5. последняя строка - возврат на главный экран.

Результат предыдущего действия показывается отдельным blockquote над экраном. Он не смешивается с постоянными показателями.

## Главный экран

Главный экран отвечает только на четыре вопроса:

- кто я и какой сейчас день;
- что происходит с проектом;
- сколько активностей осталось сегодня;
- в каком состоянии основные карьерные показатели.

Подробная информация вынесена в отдельные разделы.

## Навигация

Главные приоритеты расположены выше:

1. Проект и Входящие;
2. ключевые действия развития;
3. Вложения и Карьера;
4. История;
5. тестовые админские функции.

Кнопки называют действие или сущность напрямую. Нельзя использовать абстрактные подписи вроде `Далее`, если пользователь может не понимать, куда именно попадёт.

## Эмодзи

Эмодзи используются в основном на кнопках как визуальные якоря. В тексте экранов применяются обычные заголовки, числа и короткие статусные формулировки.

Не использовать несколько эмодзи в одной строке статистики и не дублировать ими смысл каждого предложения.

## Формулировки

- короткие предложения;
- один термин для одной сущности во всей игре;
- результат действия сначала говорит, что произошло, затем - что изменилось;
- ошибки объясняют, что сделать дальше;
- никакого технического языка из реализации.

## Потоки

### Входящие

После выбора автоматически показывается следующая непрочитанная ситуация. Пользователь не должен каждый раз возвращаться к списку из шести пунктов.

### Фокус-сессия

Три шага идут последовательно. После последнего шага пользователь автоматически возвращается к экрану проекта и видит общий результат.

### Проект

Экран явно объясняет разницу между `Фокус-сессией` и `Быстрой работой`. Если действий нет, кнопки работы скрываются, а не оставляются заведомо нерабочими.

## Критерий качества

Игрок без инструкции должен за несколько секунд понимать, что сейчас важно и какую кнопку нажать для следующего осмысленного действия.
