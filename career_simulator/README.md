# Карьерист

Telegram-симулятор карьеры. Игрок начинает стажёром и растёт за счёт реального навыка, репутации, заметности и связей, одновременно управляя стрессом и дедлайнами.

## Стек

- Python 3.12+
- aiogram 3
- SQLite (`sqlite3`, без ORM)
- python-dotenv

LLM в базовую версию не встроена: основной игровой цикл должен быть дешёвым, детерминированным и тестируемым. Позже LLM можно добавить для редких сюжетных событий, не связывая с ней игровую экономику.

## Запуск

```bash
cd career_simulator
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

В `.env` указываются токен бота и Telegram ID администраторов:

```text
BOT_TOKEN=123456:your_bot_token
ADMIN_IDS=123456789,987654321
DB_PATH=career_simulator.sqlite3
```

`ADMIN_IDS` — список числовых Telegram ID через запятую. Сам `.env` находится в `.gitignore`, поэтому реальные токены и ID не попадут в публичный репозиторий.

Запуск:

```bash
python3 -m app.main
```

## Админские функции

Администраторы задаются через `ADMIN_IDS`.

- `/reset` — сбросить весь прогресс своего персонажа. Перед удалением бот просит подтверждение. Настройка быстрого режима не сбрасывается.
- `/fast` — переключить быстрый режим.
- `/fast on` и `/fast off` — явно включить или выключить быстрый режим.
- В главном меню админа есть кнопка состояния быстрого режима.
- Когда быстрый режим включён и все 5 дневных действий потрачены, появляется кнопка `⏭ Следующий день`.

Быстрый режим не даёт бесконечные действия. Он только позволяет вручную запустить обычный переход на следующий карьерный день без ожидания 04:00 МСК. При переходе штатно обрабатываются зарплата, стресс, дедлайны, карьерные ревью и новые проекты. Дневные события и покупки предыдущего ускоренного дня архивируются и не мешают тестировать следующий день.

## Структура

```text
career_simulator/
├── app/
│   ├── admin.py        # админские функции и быстрый режим
│   ├── config.py       # конфигурация
│   ├── content.py      # ранги, события, проекты, покупки
│   ├── db.py           # схема SQLite
│   ├── game.py         # игровая логика
│   ├── handlers.py     # Telegram-хендлеры
│   ├── keyboards.py    # inline-кнопки
│   └── main.py         # точка входа
├── docs/
│   ├── GAME_DESIGN.md
│   └── DATA_MODEL.md
└── tests/
```

Главное правило архитектуры: Telegram ничего не решает сам. Хендлеры только принимают нажатия и вызывают игровые сервисы; баланс и правила находятся вне Telegram-слоя.
