# Wasteland Settlement Strategy — playable draft

Текстовая стратегия в сеттинге `wasteland_rpg` («Контур»).

Игрок руководит **Приютом-7**: следит за запасами, управляет жителями, собирает отряды, отправляет их в пустошь, развивает поселение и постепенно открывает более опасные сектора.

Проект одновременно является игровым прототипом и вторым независимым сценарием для проверки архитектуры будущего `simulation_engine`.

## Что можно делать в Telegram

После `/start` доступно пять основных разделов:

- `🏠 Поселение` — запасы, мораль, текущие процессы и переход к следующему игровому дню;
- `👥 Жители` — состояние, характеристики, XP и обучение жителей;
- `🧭 Вылазки` — выбор сектора, сбор отряда из 1–3 жителей и отправка за припасами;
- `🏗 Развитие` — улучшение построек;
- `📋 События` — журнал последних результатов и изменений.

Вылазки, строительство и обучение занимают реальное время. Пока бот запущен, он проверяет завершившиеся процессы и присылает отдельное сообщение с результатом.

Команда `/reset` полностью сбрасывает текущую игровую сессию пользователя.

## Основной игровой цикл

```text
проверить состояние поселения
        ↓
распределить свободных жителей
        ↓
вылазка / стройка / обучение
        ↓
дождаться завершения процессов
        ↓
добыча, ранения, XP, новые уровни
        ↓
улучшения поселения
        ↓
освоение более опасных секторов
        ↓
новые решения и более дорогие риски
```

Главный ресурс — не только припасы, но и **время жителей**. Один и тот же человек не может одновременно идти в вылазку, лечиться и тренироваться.

## Что уже реализовано

- Приют-7 как управляемое поселение;
- 6 жителей;
- Сила / Ловкость / Восприятие / Интеллект;
- здоровье, усталость, XP, уровни и очки развития;
- 3 сектора: Ржавый пояс → Промзона-12 → Чёрный контур;
- освоение сектора 0–100 и последовательное открытие следующего;
- отряды из 1–3 жителей;
- расходы еды, воды и боеприпасов на вылазки;
- реальное время завершения вылазок;
- deterministic random для воспроизводимых результатов;
- добыча, шанс провала и ранения;
- Водосборник, Теплица, Медпункт, Тренировочный двор и Наблюдательная вышка;
- строительство с ценой и временем;
- обучение характеристик;
- суточное потребление и производство еды/воды;
- лечение и восстановление усталости при переходе дня;
- event log;
- idempotency действий;
- Telegram UI на aiogram 3;
- фоновая проверка завершившихся процессов;
- тесты ключевой предметной логики.

## Важное ограничение draft

Игровые сессии пока хранятся **в памяти процесса**. Если остановить и заново запустить Python-процесс, прогресс игроков сбросится.

Это сознательное ограничение текущего vertical slice. Следующий инфраструктурный шаг — вынести состояние, timers и idempotency в SQLite либо подключить готовый persistent runtime из `simulation_engine`, когда он появится.

## Запуск Telegram-бота

Из корня репозитория:

```bash
cd wasteland_settlement_strategy
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
cp .env.example .env
```

Открой `.env` и укажи токен:

```env
BOT_TOKEN=123456:your_token_here
```

После этого запусти:

```bash
python3 -m app.main
```

Открой своего бота в Telegram и отправь:

```text
/start
```

Управление идёт через inline-кнопки под сообщениями.

## Связь с simulation_engine

`app/prototype_runtime.py` — не отдельный универсальный движок. Это временная исполняемая прослойка, повторяющая ключевую форму будущего API:

```text
Action
  ↓
handler
  ↓
state changes + Events + Timers
  ↓
atomic commit
```

В draft уже используются:

- typed Actions;
- Domain Events;
- единая транзакционная граница действия;
- idempotency key;
- deterministic Clock;
- seeded Random;
- scheduled triggers;
- UI, отделённый от scenario logic.

Когда `simulation_engine` получит исполняемый runtime, `prototype_runtime.py` должен исчезнуть, а предметная логика `scenario.py` — подключиться к настоящему Engine.
