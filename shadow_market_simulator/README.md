# NIGHTSHIFT

NIGHTSHIFT — асинхронный экономический симулятор для Telegram. Игрок управляет магазином: закупает товар, распределяет его через команду, настраивает витрину, следит за продажами, выплатами, риском и диспутами.

## Стек

- Python 3.12+
- aiogram 3.30
- SQLite3
- python-dotenv
- pytest 8

## Запуск

```bash
cd shadow_market_simulator
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Укажи `BOT_TOKEN` в `.env`, затем запусти:

```bash
python -m app.main
```

Новая установка не требует старой БД. `Database.init()` создаёт SQLite-схему из `app/core/schema.sql`, а дополнительные runtime-таблицы создаются идемпотентно соответствующими подсистемами. Миграционного фреймворка и цепочки старых миграций в проекте нет.

Повторный запуск текущей версии с той же БД безопасен. При несовместимом изменении схемы существующей БД автоматического преобразования таблиц нет; релизная схема рассчитана на текущую версию кода.

## Конфигурация

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | Telegram Bot API token | обязательно |
| `ADMIN_IDS` | Telegram ID администраторов через запятую | пусто |
| `DB_PATH` | путь к SQLite-файлу | `shadow_market.sqlite3` |
| `SIMULATION_INTERVAL_SECONDS` | период фонового цикла | `30`, минимум `10` |
| `SIMULATION_SPEED` | базовый параметр конструктора симуляции | `1.0` |

Фактическая скорость игровых таймеров хранится для каждого игрока в `settings.time_multiplier` и меняется административной командой `/speed`.

## Игровой цикл

```text
Товар → покупка → получение складменом → Склад
→ передача закладчику → подготовка и фасовки → Витрина
→ продажи → оценки / диспуты → выплаты и аналитика
```

Новый игрок начинает с пустым складом и 500 000 ₽ свободных денег. Первое прохождение ведёт через закупку, получение товара, передачу закладчику, витрину, продажу и диспут.

Главное меню содержит пять основных разделов:

- `📨 Входящие` — события, уведомления и диспуты;
- `📦 Товар` — рынок предложений и склад;
- `🏷 Витрина` — цены, остатки и фасовки;
- `👥 Команда` — сотрудники, найм, условия оплаты и развитие закладчиков;
- `📊 Аналитика` — обзор бизнеса, товары, деньги и выплаты.

Подробное описание реализованной модели: `docs/GAMEPLAY.md`.

## Структура проекта

Архитектура v2 завершена. Игровая логика разнесена по feature-пакетам; старые root compatibility-файлы и runtime overlay-модули удалены. В корне `app/` остаются только сборка приложения и Telegram UI.

```text
shadow_market_simulator/
├── app/
│   ├── main.py
│   ├── bootstrap.py
│   ├── core/              # конфигурация, Database, базовый GameService, schema.sql
│   ├── engine/            # базовая симуляция, игровое время и таймеры
│   ├── bot/               # middleware и фоновые уведомления
│   ├── commerce/          # закупка, склад, workflow, фасовки
│   ├── staff/             # найм, оплата, отношения, аналитика сотрудников
│   │   └── couriers/      # модель и управление курьерами
│   ├── disputes/          # выплаты по диспутам
│   ├── trust/             # рейтинг и доверие покупателей
│   ├── analytics/         # бизнес-аналитика и event log
│   ├── inbox/             # lifecycle входящих сообщений
│   ├── tutorial/          # onboarding и гарантии первого цикла
│   └── ui_*.py            # Telegram routers/renderers
├── docs/
│   ├── ARCHITECTURE.md
│   ├── ARCHITECTURE_STATUS.md
│   ├── GAMEPLAY.md
│   └── DATA_MODEL.md
├── tests/
├── .env.example
├── requirements.txt
└── README.md
```

Внутренний код импортирует только канонические package-paths. Новые `*_update.py`, `*_fixes.py`, compatibility-facades и runtime monkey-patching запрещены архитектурными guardrails.

`docs/ARCHITECTURE.md` описывает актуальные архитектурные правила и границы ответственности. `docs/ARCHITECTURE_STATUS.md` фиксирует фактическое состояние architecture v2. `docs/DATA_MODEL.md` перечисляет важные таблицы и связи.

## Тестирование

Из папки `shadow_market_simulator`:

```bash
python -m pytest -q
```

CI дополнительно запускает `compileall`, ruff-проверку ошибок импортов и имён, smoke-тест свежей SQLite-базы, рекурсивную проверку устаревших NIGHTSHIFT-контрактов и архитектурные guardrails. `tests/test_architecture_guardrails.py` не позволяет наращивать старую цепочку `SimulationEngine`/`GameService`, добавлять новые root-модули вместо feature-пакетов и распространять runtime monkey-patching. `tests/test_zzzz_release_audit.py` отдельно проверяет релизную композицию: пустой старт, актуальный onboarding, применение накопленных изменений оплаты и защиту подтверждающих callback от повторного выполнения.

## Ограничение развёртывания

Один SQLite-файл предназначен для одного процесса бота. Несколько одновременно работающих процессов с общей БД не являются поддерживаемой конфигурацией: фоновые уведомления и runtime рассчитаны на single-process long polling.
