# Витрина и компенсации

## Витрина

Новый UX строится в два уровня:

1. выбор товарной категории;
2. выбор фасовки конкретной категории.

Корневой экран показывает общий остаток товара. После выбора категории для каждой фасовки рассчитывается число доступных позиций:

```text
available_positions = floor(total_stock_units / pack_size)
```

Все фасовки используют один общий остаток. Поэтому показатель `поз.` означает потенциальное количество позиций такой фасовки при текущем остатке, а не отдельный физический пул товара.

Карточка фасовки показывает:

- текущую цену;
- цену за единицу;
- отклонение от базовой игровой цены категории;
- общий остаток;
- число доступных позиций;
- inline-кнопки ±5%.

Каталог использует общие категории `Стимулятор`, `Эмпатоген`, `Каннабиноид`. Они заменили абстрактные бренды Neon/Amber/Echo. Денежные значения являются внутренними параметрами баланса игры и не копируют актуальные предложения реальных нелегальных площадок.

## Компенсации по диспутам

Решение разделено на два этапа.

### Этап 1: размер

Игрок выбирает:

- 100% стоимости заказа;
- 50% стоимости заказа;
- отказ.

Отказ закрывает диспут без выбора источника.

### Этап 2: источник

Для компенсации показываются два возможных источника:

- счёт магазина;
- депозит сотрудника, выполнявшего заказ.

Экран показывает текущие доступные суммы. Источник с недостаточным остатком блокируется на уровне интерфейса и повторно валидируется в сервисном слое.

### Списание со счёта магазина

```text
shop.balance -= refund
shop.total_profit -= refund
```

Ledger получает обычную запись `refund`.

### Списание из депозита сотрудника

```text
shop.balance -= refund
employee.deposit -= refund
employee.losses += refund
```

`total_profit` магазина дополнительно не уменьшается: денежный актив и обязательство перед сотрудником сокращаются одновременно.

Ledger получает тип `refund_employee_deposit`.

### История

В `disputes` сохраняются:

- `refund_amount`;
- `refund_source` (`shop`, `employee`, `none`);
- `refund_employee_id`.

Это позволяет позже добавить аналитику:

- сколько компенсаций оплатил магазин;
- сколько списано с сотрудников;
- какие сотрудники чаще теряют депозит;
- связь между причиной диспута и выбранным источником компенсации.

## UX-принцип

На каждом шаге есть кнопка возврата:

```text
Диспут → Размер компенсации → Источник средств
                       ↑             |
                       └── Назад ────┘
```

Игрок не должен случайно списать деньги одним нажатием из карточки диспута.
